### 沙箱导致的三条硬约束（后续所有构建命令都要遵守）

1. **`.bat` 无法执行**（`sdkmanager.bat` / `gradlew.bat` 报"拒绝访问"）→ 一律直接调 java 主类：
   `sdk.ps1` 调 `com.android.sdklib.tool.sdkmanager.SdkManagerCli`；构建走 `build.ps1`（内部调
   `java -cp gradle\wrapper\gradle-wrapper.jar org.gradle.wrapper.GradleWrapperMain assembleDebug`）
2. **写盘只能落在工作区内** → `GRADLE_USER_HOME`、npm 缓存、`user.home` 全部重定向到 `tools/` 下
   （`tools/gradle-home`、`tools/npm-cache`、`tools/home`），由 `novel-ai-tool/env.ps1` 统一设置
3. **`.ps1` 里不能放中文字符串字面量**（新增，已踩过）：Windows PowerShell 5.1 把无 BOM 的 `.ps1` 按本地
   ANSI 页解码，多字节序列会破坏它的 tokenizer，报“字符串缺少终止符”“必须在 `-` 运算符后面提供一个值表达式”。
   规则：**构建脚本一律 ASCII**（中文注释可用，字符串字面量不要用）；界面/业务文案的中文在 `.html`/`.js`/`.css`
   里，不经 PowerShell，不受此限制。验证方法：`[System.Management.Automation.Language.Parser]::ParseFile(...)`
   看 errors 是否为空（已写入 `build.ps1` 顶部备注）。

构建入口：`cd novel-ai-tool; .\build.ps1`（含 `cap sync` + 出包 + `aapt2` 产物核对）；实测增量构建
`BUILD SUCCESSFUL in 1m 5s`，产物 `android/app/build/outputs/apk/debug/app-debug.apk` 12.68 MB。

## 三、明确不使用

| 组件 | 不用的原因 |
|---|---|
| Android Studio / IntelliJ | 只用命令行 + VSCode 即可构建，省 3 GB 以上占用 |
| Chaquopy | 未授权构建有运行时限、商用收费，与"纯开源"要求冲突 |
| python-for-android / Buildozer | 需 WSL2 或 Linux；本机 WSL 未安装且虚拟化未开 |
| Termux + PWA | Termux 发行包只在 GitHub/F-Droid，`github.com` 与 `f-droid.org` 实测返回 `000` |
| 端侧大模型（llama.cpp / MLC） | 质量与包体不划算；架构上靠可配 `base_url` 留出局域网 Ollama 口子 |
| Vite / webpack 等前端打包器 | 界面是纯静态 `www/`，Capacitor 可直接指向静态目录，减少一层构建风险 |
| Emulator（AVD） | 虚拟化未启用；改用手机 USB 调试（用户已选） |
